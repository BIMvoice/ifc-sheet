Joinery configurator, second slice. A door or window type configured by hand now keeps its own windows: an element whose IFC type is mapped uses that mapping, and the name and size rules never pick an entry that belongs to a type, so in a model with two window types of one name, configuring one no longer pulls the other type's windows into its row. A type can have an arched head (round, segmental with a rise, or pointed), which shapes the schedule's elevation outline and the opening lines inside it (leaves under a fixed light are clipped by the arch too); the overall size stays the IFC's and the plan is unchanged. Properties can be added to a type by hand (thermal transmittance and fire rating are suggested, any name is allowed): they are kept in the project, not written to the IFC, shown in the joinery schedule (the U value and fire rating in their own rows; every other name is offered by a schedule's "Add a column" under the set "Typed for the type" and is then a model row of `content.properties` like the model's, so it can be hidden, moved and typed over) and read by the headless engine. A configured type whose windows state no size prints the size measured from their geometry, marked with ≈, instead of the kind's default. English and Romanian.
