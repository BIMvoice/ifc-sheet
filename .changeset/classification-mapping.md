Classification mapping (#89). The office maps IFC classes, types and materials to the codes of a classification system (Uniclass, OmniClass or its own) in a new **Classification codes** section of the project drawer: the model's classes, types and materials are listed with the ones that have no code marked, a code and title are typed per item, one code can be given to every type of a class at once, and a CSV (code, title, and one of class, type or material per row) can be imported; a row that cannot be taken is listed with its row number, never dropped quietly. IfcSheet ships no code table (Uniclass and OmniClass are licensed). The mappings are saved with the project and travel in the `.bvlib` library (a new `classificationMappings` kind, merged by system under the three policies). One engine function, `classificationOf(element, mappings, model)`, answers for tags, schedules, the CSV and XLSX and the command line: the model's own IfcClassificationReference wins, else the mapping by type, then material, then class. The quantities by type gain a classification column (code and title) and can group the types under their code; the TAG tool and annotation types gain "Classification code" and "Classification title" fields and labels the `{Classification}` and `{ClassificationTitle}` placeholders. `ifcsheet classify <model.ifc> --project <file>` prints the model's types with their codes.
