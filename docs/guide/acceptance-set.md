# Milestone 1 acceptance set

The fixed set of real models behind the Milestone 1 goal (#557): IFC in, correct drawings out. The suite is
`packages/ifcsheet/src/acceptance/m1.acceptance.test.ts`. It runs headless (no browser) with the package's other tests
(`pnpm --filter @bimvoice/ifcsheet test`, and `turbo test` in CI), in about 6 seconds without the school and about 35 seconds with it.

Each model is opened, its starting set is generated and each view cut. Then the same set is printed through the command line as a project
(`ifcsheet build <model> --project <file> --out set.pdf --dxf <dir>`) with a drawing register sheet added.

## What every model checks

- The file is the one the figures were written for: its storeys, door count and window count.
- A plan exists for each storey and has cut walls (a storey the cut passes above is named in the model's row as empty and must stay empty).
- Doors and windows are cut on the plans, and the plans draw every one of them except those the model's row lists by GlobalId (the school: nine, see below).
- Sections have cut faces, through the classes the model must cut (slabs, walls).
- The room schedule has the model's room count (models with no room skip this).
- The drawing register lists the set's sheets in set order, and the register page of the printed PDF names every sheet number and title.
- The PDF has a page per sheet and every sheet has a DXF that parses and holds entities.

A figure an empty drawing would also give (zero windows in a model with none) is not asserted.

On the school the plans draw every door and window (the roof storey's plan cuts nothing). The eight curtain wall doors (parts of an IfcCurtainWall,
not contained in the storey themselves) are drawn since #586, and so are the nine that lie wholly above or below their storey plan's 1.2 m cut (seven wall
hatches and two small windows whose sill is 1 cm above the cut): a plan draws the symbol of a door or window whose host wall it cuts (`opening-hosts.ts`).
`notDrawn` is empty; it lists by GlobalId any door or window no plan draws, and an id is never added. It also found that the DXF writer overflowed the stack on its elevations, which is fixed with the suite.

The suite checks that doors and windows are cut and drawn on the plans, and (#587) that the plans carry their symbols: per model, the door symbols
the engine draws (`planOpeningSymbols`, the code the app calls) number more than none, are symbols of doors the plan draws, and cover every door
the plan cuts; and the printed sheets carry a `SYMBOLS` pen. The swing and opening symbols of doors and windows are drawn by the engine on plans, and (since the elevations' share of #587) on elevations and
sections: a second check per model counts the door symbols the four elevations draw (`elevationDoorSymbols`, the least the model gave when it was written),
requires each to be of a door the elevation shows, and requires the elevation sheets to carry a `SYMBOLS` pen exactly when there are some. A window has no symbol
on an elevation until it has a configured or mapped type, in the app and here, so these models (none maps its windows) show door symbols only; the window, glazing bar,
arched head and transom symbols are checked by the parity test on FZK. The skolebygg model is optional and absent here, so its count is 0 until someone with the file sets it.

The six models after the school (#557, ten in all) are read from `tests/models` and skipped with a message when absent (CI never fetches them). The gaps listed in their notes are defects the widening found: `notDrawn`, `doorsWithoutSymbol` and `mergedLevels` in the suite record them so the suite stays green and shrinks when they are fixed; an id is taken out when its element is drawn.

Other models in the repository (hello-wall, building-architecture, the Bonsai, Revit and Archicad exports from the user calls) are not in the set:
their provenance or licence is not recorded, or they need a fixture file nobody has committed. Add one with a row in `CASES`, the counts read
from the file, and a line in the table above.
